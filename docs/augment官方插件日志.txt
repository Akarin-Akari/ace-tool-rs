当你需要撤销一个已经推送到公共分支的提交时。\n    *   **命令**: `git revert <commit_hash>`\n    *   **原理**: `revert` 会创建一个**新的提交**，这个新提交的内容是目标提交的“反操作”，从而抵消其影响。\n    *   **优点**:\n        *   **保留历史**: 不会删除任何提交记录，保证了版本历史的完整和透明。\n        *   **团队友好**: 不会影响其他成员的工作，是一个安全的回滚方式。\n\n*   **【警告】谨慎使用 `git reset --hard` (危险的重置)**\n    *   **场景**: **仅限于在你自己的、未推送的私有分支上**，用于丢弃一些不想提交的本地修改。\n    *   **命令**: `git reset --hard <commit_hash>`\n    *   **原理**: 直接将分支的 HEAD 指针移动到指定的提交，并丢弃该提交之后的所有历史。\n    *   **后果**:\n        *   **历史丢失**: 会永久性地删除提交历史，一旦推送到远程，其他人将无法找回。\n        *   **协作噩梦**: 如果在公共分支使用，会造成团队成员历史记录混乱，甚至丢失代码。**本次事故的罪魁祸首就是它！**\n\n### 2. 禁止强制推送 (`force push`)\n\n*   `git push --force` 或 `git push -f` 会强行用你的本地分支覆盖远程分支。\n*   它通常与 `git reset` 配合使用，是造成远程仓库历史被篡改的直接原因。\n*   **规则**: 在任何情况下，都**禁止**向 `master`、`main`、`aitest` 分支执行强制推送。\n\n### 3. 分支保护与 CODEOWNERS (终极防护)\n\n为了从制度上防止误操作，建议在 GitHub/GitLab 上进行如下配置：\n\n*   **分支保护规则 (Branch Protection Rules)**:\n    *   为 `main` 和 `aitest`
